# ADR-0017：只按已导入数据评估；覆盖度显式声明与数据健康度自检

- 状态：Accepted
- 日期：2026-07-26
- 决策者：Human
- 关联迭代：`docs/iterations/2026-08-r1-layer-contract-skeleton.md`

## 背景

ficant 是开源平台，部署在用户本地。用户的持仓、主体信息、行情源很可能只有一部分被导入——其余仍在其他部门、其他系统或表外。

由此产生一个真实问题：当用户问"我还剩多少额度"时，ficant 到底能不能答？

若按 ficant 看得见的持仓计算占用，结果会**系统性低估**；而用户很可能把"覆盖了 60% 持仓的占用率"当成真实占用率使用。这属于数据问题里最恶劣的一类——**它不报错，只是让人得出自信而错误的结论**。

曾评估过的做法是让用户申报"外部已占用额度"。但这是在索要一个用户自己也未必准确的数字，且该数字无法校验，反而会让错误看起来像是经过核算的。

## 决策

**ficant 对未导入的数据不做任何猜测，只按已有数据评估；同时以显式覆盖度声明与平台自检弥补由此产生的认知缺口。**

### 一、不猜测

- 任何计算只使用已导入 ficant 的数据。
- **不引入"外部已占用"之类的用户申报字段。**
- 计算结果的语义是"基于已导入数据的 X"，不是"真实的 X"。

### 二、覆盖度显式

计算结果必须携带其输入的**覆盖度声明**，至少包含：参与计算的仓位数与总额、缺失关键字段的记录数、各字段的可信度分布。

**覆盖度未声明的结果不得作为组织级结论呈现。** 界面与报告不得输出裸数值。

### 三、平台数据健康度自检

新增平台级自检能力，产出可查询的 `DataHealthReport`。它以 `AnalyticsService` 形态承载（见 ADR-0016），检查项包括但不限于：

| 类别 | 检查项 |
|---|---|
| 缺失 | 持仓为空或长期未更新；主体无对应状态快照；行情源注册后无数据 |
| 完整性 | 有仓位但无对应 Instrument 定义；有 Instrument 但无现金流条款 |
| 分类 | 会计分类为 `UNKNOWN` 的仓位数与占比 |
| 可信度 | 价格来源类型缺失的记录占比；纯模型估值占比 |
| 时效 | 快照陈旧程度；规则包是否已过生效期 |
| 一致 | 多源数据分歧超阈值的记录 |

**自检不阻断计算，但其结论必须可见。** 缺失与异常以预警形式呈现，用户可据此决定是否补数据。

### 四、与失败关闭的分工

两种机制职责不同，不可互相替代：

- **失败关闭**用于"缺了就一定算错"的情形——会计分类未知时的资本占用（ADR-0011）、主体未绑定时的 IRR（ADR-0012）、规则包缺项时的交割计算（ADR-0013）。
- **健康度预警**用于"缺了仍能算，但结论的适用范围变窄"的情形——持仓覆盖不全、部分价格无来源标记。

判据：**缺失是否会让结果在其自身声明的范围内也变错。** 会，就失败关闭；不会，就预警加覆盖度声明。

## 备选方案

1. **要求用户申报外部占用。** 否决：索要用户自己也不准的数字，且不可校验，会把猜测包装成核算。
2. **数据不全时一律拒绝计算。** 否决：开源平台上数据永远不全，这会让平台在绝大多数部署中不可用；且"部分数据的正确结论"本身是有价值的。
3. **静默按已有数据计算，不做声明。** 否决：这正是本 ADR 要防的失败模式。
4. **健康度检查做成阻断式门禁。** 否决：健康度是连续的而非二值的，阻断阈值必然武断；且会诱使用户填假数据以通过门禁。

## 后果

- 新增一类平台级能力（自检），它不产生研究结论，但决定研究结论的可信范围。
- 所有对外呈现的数值都需要承载覆盖度元数据，界面与报告层的表达成本上升。
- 用户不导入持仓则组合级功能不可用、不填会计分类则资本占用不可用——这些代价是有意的，并由健康度报告明确告知，而非静默失效。
- 本 ADR 引入的横切原则已写入 SPEC v1.1 的不变量 **I10（覆盖度显式）**，含与失败关闭的分工判据。

## 验证与失效条件

- 验证：ACCEPTANCE `AC35`（组合级结果携带覆盖度声明，裸数值不出现在任何输出中）、`AC36`（缺失时健康度报告列出具体项并预警，且不阻断计算）。
- 失效条件：若健康度预警在实际使用中被普遍忽略（用户长期在低覆盖度下使用结论），则"预警而不阻断"的判断需重新评估，可能需要对特定高风险结论改为失败关闭。
