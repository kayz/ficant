# ADR-0024：逐 bar 点时回放

- 状态：Accepted
- 日期：2026-10-23
- 决策者：Human（2026-10-23 在对话中确认四处选择：内置策略族、下一根 bar 成交、VWAP 否则收盘价、Application 用例）
- 范围：SPEC v1.4 §4.2「研究闭环」中的点时回放与仿真运行；AC38、AC39，并为 AC40–AC44 定接口
- 关联：ADR-0012（Subject）、ADR-0014（PolicyArtifact 与共用求值器）、ADR-0023（标准 Bar 与点时读取）

## 背景

二期的链路是：

> 点时快照 → PolicyArtifact → 逐 bar 点时回放 → 仿真成交 → 每日持仓与损益分解 → 标定 → 输出

前两步已经就位（ADR-0023）：Bar 快照不可变，`VerifiedBarSnapshot::visible_at(t)` 只返回 `visible_at ≤ t` 的 Bar，越过快照截止就失败。本 ADR 定义回放本身。

要满足的判定条目：

- **AC38**：任一决策时点用到的每条记录 `visible_at` 不晚于该时点；向快照追加一条更晚才可见的记录，该时点及之前的结果不变。
- **AC39**：同一 PolicyArtifact、快照、Subject、成本模型参数与种子，结果逐位相同；替换任一要素，结果标识随之改变。
- 后续（本 ADR 只定接口）：AC40 损益分解、AC41 参与率与无价不成交、AC42 约束、AC43 标定、AC44 输出无订单对象。

ADR-0014 已经定下：策略以 `PolicyArtifact` 交付，回测和实盘调用**同一份求值器实现**，求值器是可链接的库，不是服务。

## 决策

### 1. 策略的形式：求值器接口 + 内置策略族

```
trait PolicyEvaluator {
    fn decide(&self, params: &PolicyParams, view: &PointInTimeView, book: &SimulatedBook)
        -> Result<TargetExposure, PolicyError>;
}
```

- `PointInTimeView` 是唯一的数据入口：它由回放引擎在每个决策时点用 `visible_at(t)` 构造，策略拿不到快照本身，也拿不到时钟。看不见未来是结构保证，不靠策略作者自律。
- 策略输出 `TargetExposure`（每个工具的目标面额），不是订单（AC44）。
- 策略看到的持仓是"已结算持仓 + 尚在等待执行 bar 的交易"。等待中的交易能否成交取决于一根尚不可见的 bar，所以只按意图计入，不按结果计入；交易结算为未成交后，下一个决策时点看到的持仓自然回退，策略会重新提出。
- 二期先提供 Rust 内置策略族（参数化，例如"目标久期 / 收益率阈值"类），求值器即 ficant 的库代码，满足 ADR-0014 的"同一份实现"。
- 用户自写代码（Python）属于三期"生成式研究节点"，需要沙箱与节点契约，不在二期。

### 2. 决策与成交的时序

- 决策时点：回放频率下每个 bar 的**可见时间**。只有某根 bar 可见之后，才在该时点做决策。
- 成交：决策产生的目标与当前持仓之差，在**开始时间不早于决策时点的下一根 bar** 内仿真成交。绝不在做出决策的那根 bar 内成交，这一点防止用"已结束 bar 的收盘价"成交。
- 成交价格取该成交 bar 的 VWAP；没有 VWAP 时取收盘价；该 bar 无成交时不成交，并记录原因与价格来源类型（AC41）。
- 成交量上限：该 bar 成交量 × 策略声明的参与率上限（AC41）。超出部分顺延到后续 bar，或按 PolicyArtifact 声明作废。

### 3. 结果的身份（AC39）

一次回放的结果标识是以下全部输入的内容哈希：

- PolicyArtifact（策略族、版本、参数、券域、有效期）；
- Bar 快照（snapshot ID 与内容哈希）；
- Subject 版本与 SubjectStateSnapshot（ADR-0012；资金成本取自其资金档，AC40）；
- 成本模型及其参数；
- 种子；
- 代码与运行环境摘要（沿用现有正式输出证据，R7B）。

引擎本身不使用随机数、不读系统时钟、对集合按确定顺序迭代，因此同样输入逐位相同。种子只交给需要随机性的成本模型；不需要时也记入标识，保证"换了种子"总能体现在标识上。

### 4. 运行位置与输出

- 回放是 Application 层的用例，直接在进程内调用领域求值器与快照读取，不经过现有研究图的 Worker 执行。
- 输出 `SimulationResult`：每个决策时点的目标、每笔仿真成交、每日持仓与损益（AC40 补齐分解），带完整血缘与覆盖度声明。
- 本 ADR 不改 `interface/proto/**`、不加 migration。持久化与 gRPC 接口另行提出。
- 数据经端口 `PointInTimeBars` 进入回放；它的 `visible_at(t)` 由 `VerifiedBarSnapshot` 实现。即使端口实现有误、把未来的 bar 交出来，`PointInTimeView` 的构造也会拒绝，回放整体失败。
- 引擎核心（视图、持仓、成交模拟、结果标识）在 L1 领域层的新模块 `ficant_domain::replay`，是纯函数；Application 用例只负责调度。这样 ADR-0014 的"共用求值器"可以直接链接领域库。
- 二期新增的 L1 对象放在新模块里，不改 `primitives/` 与 `research/` 已有文件：R7A 门禁冻结了这些文件的精确内容，作为"新增市场不改核心"的证据（AC 证据，不能为了新功能重写）。

### 5. 第一个实现 PR 的范围

- 领域：`PolicyArtifact`（最小字段）、`PolicyEvaluator`、`PointInTimeView`、`SimulatedBook`、`SimulationResult` 与结果标识；
- 一个内置策略族，用于测试；
- 回放引擎：决策时序、下一 bar 成交、无价不成交；
- 测试：AC38（每个决策时点的输入都满足可见性；追加晚可见记录不改变之前结果）、AC39（逐位相同；逐一替换六类输入，标识都改变）；
- 成本、参与率、约束、损益分解、标定分别在后续 PR 中补上。

## 代价

- 二期只能用内置策略族，研究员不能自写策略代码；自写代码要等三期的节点契约与沙箱。
- 下一 bar 成交意味着策略比"理想成交"慢一个 bar。这是有意为之：它是不偷看的最简单可审计规则。

## 替代方案

- **在决策 bar 的收盘价成交**：拒绝。该价格在决策时点才刚可见，用它成交等于假设零延迟，是回测偏差的常见来源。
- **把回放放进现有研究图，由 Worker 执行**：暂不。研究图是为节点化分析设计的，回放是逐步有状态的循环；先作为用例实现，稳定后再考虑节点化。
- **二期就支持 Python 策略**：暂不。没有沙箱与节点契约就执行用户代码，会破坏确定性与安全边界。
