# ADR-0009：采用 OPAID 本地开发与 CICD 发布边界

- 状态：Accepted
- 日期：2026-07-17
- 修订：2026-07-20（Human brief 交付与版本 tag 触发）
- 范围：任务冻结、本地开发与测试、候选交接、CI/CD、发布和历史治理材料
- 取代：ADR-0008 的活动 HOQA 治理机制

## 背景

FICANT 已有多语言业务代码、自动化测试和可运行的 GitHub 测试环境发布链路。旧 HOQA 同时覆盖开发治理、测试参与者、SIT、交付和关闭，活动状态还依赖 `.hoqa` 与 checklist；中央 `cicd` 又已经承担正式 CI、镜像和部署。这形成了本地候选管理与发布管理的重叠权威。

本决策不改变已接受的产品事实、技术 ADR、业务实现、测试 Oracle、历史缺陷、风险接受或发布证据，只重新划分今后的活动责任。

## 决策

OPAID 是从任务冻结到精确本地自测候选的唯一活动开发方法。每轮由 Root Orchestrator 冻结代码结果、验收句、非目标、精确 base、本地自测、路径所有权和公共契约；有实际并行收益时才使用互斥写路径的直接 Worker。最终结论必须绑定集成候选上的真实命令、退出码和测试数量。

OPAID 的退出交付物是精确本地自测候选与唯一 Human brief。Human 阅读 brief 后，可以要求在同一候选上运行一次完整本地检查（本地 CI）并人工复测，也可以接受现有证据、合并并进入下一迭代。这两个选择都不触发 GitHub 完整 CI；普通 branch push、Pull Request 和 `main` 合并只维护源码历史。

中央 `cicd` 是版本候选的唯一发布管理边界，负责 GitHub CI、Linux 制品构建、GHCR、测试环境部署、健康与冒烟检查、部署记录及回滚。数个迭代后，只有 Human 确定版本号并创建符合版本格式、指向当前 `main` 精确提交的不可变 `v*` tag，才进入该边界。创建 tag 即授权自动执行完整版本 CI、构建、扫描和测试环境交付。OPAID 不等待或报告 CI/CD 作为本地退出门，也不执行服务器管理、SIT、UAT 或发布操作。

版本 CI 失败不得通过移动或复用原 tag 改写事实。修复进入新的 OPAID 迭代，合并到新的 `main` 后，再由 Human 创建 forward-only 版本候选。版本镜像先以 Commit SHA 标识；只有全部构建和扫描成功后，才提升为同名不可变版本 tag，不维护 mutable `latest` 或 `test-latest`。

仓库提供 PowerShell 7 的 `scripts/check-fast.ps1` 和 `scripts/check.ps1`。入口使用参数数组、失败即退出和离线锁定依赖；不包含 SSH、GitHub、部署、发布或网络安装行为。需要 PostgreSQL/Ceph RGW 的回归只能由显式 `-IncludeIntegration` 选择，并只面向调用者准备的一次性本地环境。

不创建新的状态 ledger、agent registry、mailbox、治理 checklist 或活动治理目录。编排工具是运行中 OPAID 状态的来源；Git Commit、测试输出、PR、Actions、GHCR 标签和部署记录分别是候选与发布事实来源。

## 历史 HOQA 材料

ADR-0008 及归档到 `docs/history/hoqa/` 的材料保留为历史证据，用于解释当时的接受、SHA、风险和测试结论，但不再是当前工作的权威规则、恢复点或活动状态。任何历史 HOQA/PROQAID 文本都不得重新驱动角色门、迭代状态或发布判断。

ADR-0001 至 ADR-0007 的技术决策继续有效；本 ADR 只取代 ADR-0008 的活动治理部分。

## 选择依据与代价

这个边界让本地开发只优化可验证代码候选，让 Human 在迭代边界投入注意力，让中央平台只在明确版本交付时优化可重复发布，避免在每次 Agent push 上重复无人消费的远端验证。代价是普通迭代合并没有 GitHub Linux 认证；Human 必须按风险选择本地完整复测，并在创建版本 tag 后承担版本 CI 失败的响应责任。本地通过仍不代表可发布，版本候选必须经过 Linux CI、供应链与部署门；开发者也必须预先准备锁定版本和离线缓存，脚本不会自动修复环境。

## 替代方案

- 保留 HOQA 并把 `cicd` 作为其中一个 Delivery 阶段：拒绝，因为本地关闭与中央发布继续相互依赖。
- 把本地检查全部移入 GitHub Actions：拒绝，因为会失去提交前反馈，并增加 Runner 成本。
- 每个 branch push、Pull Request 或 `main` 合并都自动运行完整 GitHub CI：拒绝，因为大部分结果没有 Human 消费，重复了 OPAID 已完成的本地反馈；完整远端证据只在建立版本候选时产生。
- 让 PowerShell 入口自动安装工具或启动目标环境：拒绝，因为会引入非确定网络状态并混淆本地与发布权限。

## 后续升级条件

只有在中央 `cicd` 无法表达新的制品、环境审批或回滚合同，或者单机 Docker Compose 已不能满足多实例、高可用和资源调度需求时，才升级发布平台。只有在 OPAID 无法表达新的本地候选关系时，才重新审议开发治理；工具版本变化本身只需更新锁文件、脚本能力检查和本文档。
