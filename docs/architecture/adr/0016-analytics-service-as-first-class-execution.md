# ADR-0016：AnalyticsService 为与 ResearchGraph 并列的一等执行形态

- 状态：Accepted
- 日期：2026-07-26
- 决策者：Human
- 关联迭代：`docs/iterations/2026-08-r1-layer-contract-skeleton.md`

## 背景

ficant 此前把一切执行收敛到 `ResearchGraph → ExperimentRun → Artifact → SignalSet`。这条链对"回测一个策略"是完备的。

但业务侧列出的约四十个研究组件里，真正长成"实验"形状的只有少数几个（基差策略、招标预测、相对价值）。绝大多数是**服务**：曲线构建、税后现金流、关键期限 DV01、可变现估值、PD、预警扫描、影子价格。它们的消费者是承销、销售、资管、资金台，是**被查询的**，不是被"跑一次实验"的。

按频率分层，中间带尤其明显：**交易前查询（3 个）+ 分钟到日内（6 个）**——边际资本成本、冲击成本、渠道选择、组合穿透、残差扫描、波动率曲面、LCR/NSFR。这九个是 ficant 的职责（需要完整因子库与持仓），但要求被**服务**而非被**批处理**。把它们包装成一次性实验，表达代价很高且语义错误。

值得注意的是：Phase 2E 的 `ficant.rates.v1.RatesAnalyticsService` **事实上已经是这个东西**——幂等、绑定快照与规则版本、结果确定性可校验。但它游离在 ResearchGraph 之外，架构中没有它的位置。

## 决策

**承认 `AnalyticsService` 为与 `ResearchGraph` 并列的一等执行形态。ficant 由此具备批处理与在线服务两种运行模式。**

### 两种形态的区分

| | ResearchGraph / ExperimentRun | AnalyticsService |
|---|---|---|
| 语义 | 有状态运行，有生命周期与恢复 | **幂等查询** |
| 触发 | 提交后异步执行 | 同步应答 |
| 状态 | 有（Journal、checkpoint、lease） | **无** |
| 频率 | 批处理 | 交易前查询、分钟到日内 |
| 血缘 | 完整 | **同样完整** |

### 相同的要求

`AnalyticsService` 不是"轻量版实验"，它在以下方面与 ResearchGraph **要求相同**：

- 必须绑定数据快照、规则包版本、主体版本
- 结果必须可进血缘、可追溯、可复现
- 相同输入必须产生逐位相同的输出

### 不同的允许

- 结果**可缓存**（因为幂等）
- 不产生 RunJournal 条目，不占用 lease queue
- 不要求中断恢复语义

### 承载范围

一期：五个 rates RPC、边际资本成本查询、约束占用查询、数据健康度报告（见 ADR-0017）。
后续：冲击成本查询、渠道选择、残差扫描、组合穿透。

## 备选方案

1. **一切走 ResearchGraph。** 否决：把幂等查询包装成有状态实验，既有表达代价，又使"交易前实时查询"这类语义无法成立（提交-轮询-取结果的时延不可接受）。
2. **建独立的查询服务，不进血缘。** 否决：交易前查询的结果会直接影响交易决策，无血缘即无法事后追溯"当时为什么算出这个数"。这类结果的可追溯性要求不低于实验。
3. **维持现状，`RatesAnalyticsService` 作为特例存在。** 否决：特例会被复制。第二个、第三个 analytics service 出现时，没有统一的血缘与绑定要求，各自为政。

## 后果

- Phase 2E 的形态被正规化，不再是架构外的孤例。
- 结果缓存需要以"快照 + 规则版本 + 主体版本 + 输入"的完整键寻址，否则缓存会成为跨版本污染源。
- 两种运行模式并存增加了架构表面积；缓解方式是两者共用同一套绑定与血缘机制，只在状态管理上分叉。
- 约束占用查询（ADR-0012、ACCEPTANCE E 组）以本形态承载，是其第一个非 rates 的使用者。

## 验证与失效条件

- 验证：`AC22`（交易前返回边际占用）间接验证本形态；`AC31`（相同输入相同结果）对两种形态同等适用。
- 失效条件：若出现需要在查询链路中写入状态的真实需求（例如查询本身要计费或限流并留痕），"无状态"这一区分需重新评估。
