# ADR-0011：持仓是快照不是状态；ficant 计量不核算

- 状态：Accepted
- 日期：2026-07-26
- 决策者：Human
- 关联迭代：`docs/iterations/2026-08-r1-layer-contract-skeleton.md`

## 背景

固定收益业务的可行性研究给出一个反复出现的结论：券商自营的四个建设断点里，**科目隔离排在第一位且最该先修**——AC / FVOCI / FVTPL 三个科目的仓位往往在不同系统里，导致没有任何人能在任意时点说清全组合的关键期限 DV01。风险计量这一环断掉，资本分配就没有依据。

ficant 此前把「投资组合会计」列入不负责清单，因而没有任何持仓、组合或会计分类的表达。全 crate 检索无 `Position` / `Portfolio` / `AC` / `FVOCI` / `FVTPL`。这使得组合层面的 DV01、套保比例、约束占用全部无处落地。

同时必须避免的另一个极端是：把持仓引入后一路做成投资组合管理系统，承担变动流水、估值入账与总账——那超出了 ficant 的能力与定位，也会与机构既有系统重复。

## 决策

**持仓以快照形态进入 ficant；ficant 对持仓只做计量，不做核算。**

### 进入 ficant

- `PositionSnapshot`：不可变、点时、内容哈希寻址、可进血缘。
- 每条持仓携带**会计分类**，取值为**显式三态** enum：`CLASSIFIED`（并指明 AC / FVOCI / FVTPL）、`NOT_APPLICABLE`、`UNKNOWN`。**禁止用字段未设置表示未知。**
- 回购与债券借贷的穿透标记：正回购出去的券仍计入持仓敞口；逆回购收到的质押券不计入持仓敞口，但计入流动性视图。
- 持仓走与行情**完全相同**的双时间通道（`observed_at` / `visible_at`）。

### 不进入 ficant

持仓变动流水、估值入账、科目转换的会计处理、总账、监管报表。这些仍属机构既有系统。

### 会计分类的处理规则

- 经济视图与会计视图**并行存在**：同一仓位在不同分类下经济价值相同、会计 P&L 不同。
- 任何依赖会计分类的计算（资本占用、会计 P&L、可持有性判断）遇 `UNKNOWN` 一律**失败关闭**，并指明是哪些仓位分类未知。**不得静默退化为经济视图。**

## 备选方案

1. **持仓作为可变状态（当前持仓表 + 变动流水）。** 否决：它会立刻要求 ficant 承担核算职责；且历史结果无法绑定"当时的持仓"，回测与归因失去点时基础。
2. **会计分类用 nullable 字段。** 否决：`null` 无法区分"不适用"与"不知道"。这两者对失败关闭的判断完全不同，混同会让一个本该报错的计算静默产生错误结果。
3. **不引入持仓，由用户在外部算好 DV01 再传入。** 否决：那样 ficant 无法保证口径一致，也无法把持仓纳入血缘，全组合聚合的正确性无从验证。

## 后果

- 持仓复用 DataSnapshot 已有的全套机制（双时间、内容哈希、Ceph 存储、血缘），新增概念极少。
- **持仓数据同样会被回溯修改**（科目转换、穿透补录、漏记回购的事后修正），走双时间通道不是可选项。以过去某知识时点查询持仓，不得返回此后才补录的修正。
- 用户若不填会计分类，资本占用类功能不可用。这是有意的代价——见 ADR-0017。
- 与 README §3.2「不负责投资组合会计」的旧表述冲突；该行由 SPEC §2 与本 ADR 取代，措辞改为「不做核算与总账」。

## 验证与失效条件

- 验证：ACCEPTANCE `AC14`（持仓点时查询）、`AC16`（全组合 KRD 等于逐仓位之和）、`AC17`（未知分类失败关闭）、`AC18`（双视图并行）、`AC19`（回购穿透）。
- 失效条件：若出现真实需求要求 ficant 输出可用于对外披露的会计报表或参与总账对账，本 ADR 的"不核算"边界必须重新评估。
