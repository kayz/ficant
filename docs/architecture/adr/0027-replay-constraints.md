# ADR-0027：回放中的约束

- 状态：Accepted
- 日期：2026-10-24
- 决策者：Human（2026-10-24 在对话中确认：成交时按当时持仓检查；PolicyArtifact 按约束逐条声明拒绝或缩量）；下文「agent 补充的规则」由 agent 提出，随 PR 交 Human 审阅
- 范围：AC42
- 关联：ADR-0024（回放）、ADR-0025（账本与成交上限）、ADR-0026（约束集）

## 背景

AC42：回放中若某笔仿真成交会使任一约束突破，该成交按 PolicyArtifact 声明的处理方式（拒绝或缩量）执行，结果指明触发的约束。

ADR-0026 提供了带上限的约束（`BoundConstraint`：度量 + 上限）。ADR-0025 的成交在决策时就把所有尝试算好了；约束要按成交那一刻的实际持仓和现金判断，所以成交改为逐 bar 进行。

## 决策

### 1. 输入

- 回放请求携带完整的 `SubjectStateSnapshot` 与 Subject 的 `ConstraintSet`（`ResolveConstraintSet` 解析所得）。
- 回放把两者绑定（`ConstraintSet::bind`）。约束集必须是 Subject 的 `ConstraintSetRef` 所指的版本；状态快照必须在第一个决策时点之前已可见，否则失败关闭。
- Subject 没有绑定约束集时不执行任何约束，请求里也不能带约束集；绑定了就必须带上，且版本一致（agent 补充）。
- PolicyArtifact 新增 `constraints`：`limit_code → REJECT | REDUCE`。约束集里每条约束都必须有声明，否则回放失败关闭；声明了约束集里没有的代码，不影响。

### 2. 逐 bar 成交

- 决策时只登记交易（剩余数量、候选成交 bar）；每个 bar 结束时，账本按决策时点、工具的顺序逐笔处理落在该 bar 的成交。同一 bar 里先处理的成交会改变后处理者看到的持仓与现金。
- 每一笔先按参与率上限确定可成交量（ADR-0025），再做约束检查，然后入账。
- 没有约束时，决策、成交与损益和 ADR-0025 的预先计算相同（AC38–AC41 的测试不改断言全部通过）；结果标识的编码版本随新字段升级，所以标识值本身会变。
- 同一根 bar 里的多笔成交共用该 bar 的参与率上限（成交面额 × 上限），后处理的成交只能用剩下的部分。这修正了 ADR-0025 实现中多笔交易各自独立计上限的缺口（agent 补充，AC41）。

### 3. 约束检查

对每条约束，在「成交后」计算度量：

| 度量 | 成交后的值 |
|---|---|
| `INSTRUMENT_FACE` | 该工具的 \|持仓 + 成交量\| |
| `PORTFOLIO_FACE` | Σ \|持仓\|，其中该工具换成成交后的持仓 |
| `BORROWED_CASH` | max(0, −成交后现金)，成交后现金 = 现金 − 成交量 × (成交价 + 应计)/100 + 交易成本 |

- **突破** = 成交后的值超过上限，**且**大于成交前的值（agent 补充：降低风险的成交即使仍在上限之上也放行，否则超限的组合无法减仓）。
- 被突破的约束中，只要有一条声明 `REJECT`，这笔成交整体不成交；否则按所有 `REDUCE` 约束允许的最大量缩量，缩量后的成交保证不再突破。
- 缩量量按平台小数精度（12 位小数）向零取整；缩到零时记为拒绝。
- 结果记录：约束前的数量、触发的约束代码（按代码排序）、处理结果（`REJECTED` / `REDUCED`）。

### 4. 剩余量（agent 补充）

- 约束造成的剩余量一律作废（原因 `CONSTRAINT`），不按 `CARRY` 顺延：约束不会因为换一根 bar 而放松；策略在下一个决策时点按实际持仓重新决定。
- 卖出使借入资金上升（只可能因固定费用大于卖出所得）时无法通过缩量修复，按拒绝处理。

### 5. 结果标识

新增：状态快照 ID、约束集规则包版本、每条约束的代码、度量与上限。PolicyArtifact 的约束声明随其内容哈希进入标识。原有的 `subject_state` 版本引用改为状态快照 ID。

## 代价

- 成交改为逐 bar 处理，回放主循环更复杂；无约束时的结果由既有测试锁定。
- 上限与度量之间不校验单位：面额类约束与资金类约束的上限单位由规则包与状态快照的维护者保证。

## 替代方案

- **决策时按目标持仓检查**：实现简单，但借入资金取决于尚未发生的成交价，可能事后略微突破。Human 选择成交时检查。
- **全局一个处理方式**：更简单。Human 选择逐条声明。
