# ADR-0013：分层法则——core 定义形状，RulePack 定义内容

- 状态：Accepted
- 日期：2026-07-26
- 决策者：Human
- 关联迭代：`docs/iterations/2026-08-r1-layer-contract-skeleton.md`

## 背景

ficant 的长期目标是覆盖多个市场与资产类别。但覆盖范围扩大有一个已知失败模式：新市场的规则不断渗入核心，最终核心变成所有市场规则的并集，每加一个市场都要改核心，扩展成本随市场数超线性增长。

当前代码中该失败模式已经出现且形态危险。`crates/ficant-domain/src/futures_delivery.rs` 把中金所规则硬编码在领域层：`original_term_months()` 返回 60/84/120/360，`residual_term_bounds()` 返回 (18,27)/(48,63)/(78,None)/(300,None)。`FuturesDeliverableInput` 确实接收 `rule_pack` 并写入血缘，但**计算不从该 pack 解析任何数值**。

这比完全没有 RulePack 更危险：血缘会诚实记录"使用了 v2 规则包"，算出的却仍是 v1 的数字，**而且不报错**。属于"不报错、只让人得出自信而错误的结论"的缺陷。

## 决策

**一个概念属于哪一层，由"它因为什么原因改变"决定，不由重要性或使用者决定。**

层次定义见 `SPEC.md` §1。本 ADR 固化其五条纪律：

- **S1 依赖只能向下。** L2 定价原语不得依赖 L3 规则包；**定价原语不得内嵌任何具体市场的规则数值**。
- **S2 同层内不得有跨市场分支。** 出现 `market == X` 或等价物，即应拆为两个 pack。
- **S3 规则包必须被解析，不得只被引用。** 任何计算若声明绑定某 RulePack，其使用的每一项规则数值必须自该 pack 解析得到；解析不到即失败关闭，**禁止默认值兜底**。**"进了血缘但没进计算"视同缺陷。**
- **S4 新增一个市场所需的 L0/L1/L2 源码改动为零。** 非零即分层错误。
- **S5 因子标识全局唯一。** 见 ADR-0015。

### 具体划分规则

| 内容 | 归属 |
|---|---|
| 「有一个约束、它有上下限、它有影子价格」 | L1 形状 |
| 「自营非权益类不得超过净资本 500%」「NSFR」「LCR」「套保额度」 | L3 券商 RegulatoryRulePack |
| 「公募杠杆 140% / 200%」「保险偿付能力」 | 另外两个 L3 pack |
| 「可交割券有资格判定、有转换因子」 | L2 形状 |
| 「TS 原始期限 60 个月、剩余期限 18–27 个月」 | L3 `cgb-futures` pack |
| 「利息收入按某税率计征增值税」 | L3 TaxRulePack |
| 「这只券的税收属性锚定其首发日」 | L2 / Instrument 一等属性 |

**规则决定"怎么算"，资产属性决定"属于哪一类"。两者不可混。**

### 门禁

- `check.ps1` 纳入分层检查：在 `ficant-domain` 内检索具体市场规则数值，命中即失败；全仓库检索市场分支判断，命中即失败。
- **改动 L0 / L1 / L2 是 ADR 触发条件。** 覆盖新市场若要求改动这三层，说明形状抽错了，须以 ADR 记录并修正，不得默默接受。

### 健康度指标

持续监测：**新增一个市场所需的 L0 / L1 / L2 源码改动行数，理想值为 0。** 这是"多资产范围是否失控"的唯一客观度量。

## 备选方案

1. **维持现状，规则数值留在领域层，靠 code review 防止扩散。** 否决：约定会随并行开发漂移；agent 会不知疲倦地优化它摸得到的一切，很可能"顺手"把规则数值写回领域层当默认值。必须有自动化门禁。
2. **按资产类别分层（债券层、股票层、衍生品层）。** 否决：会得到几十个彼此重复的分支，且无法回答"同一条规则被多个资产共用"的归属问题。按定价原语与变更原因分层则收敛。
3. **RulePack 解析失败时退回内置默认值。** 否决：这正是当前缺陷的成因。静默兜底使错误不可观测。
4. **先按现状推进，等第二个市场进来再重构。** 否决：届时重构成本远高于现在，且期间产生的全部取证都建立在"规则包不起作用"的基础上。

## 后果

- Phase 2C 的取证在规则移出后**必须重跑**。Human 已批准破坏性变更。
- RulePack 的内容 schema 需要扩展以承载合约规则，这是新增工作量。
- 短期看，把常量从代码移到数据会让一次交割计算多一次解析与校验；这个代价换取的是新市场的零核心改动。
- 分层检查脚本必须在 R1 就位，否则 S1 / S2 这两条边界在 R2 之前就会被侵蚀。

## 验证与失效条件

- 验证：ACCEPTANCE `AC01`（领域层零规则数值）、`AC02`（换 pack 换结果、缺项失败关闭）、`AC03`（无市场分支）、`AC04`（新增虚构市场零核心改动）。
- 失效条件：若出现某类规则在技术上无法表达为数据（例如需要图灵完备的判定逻辑），本 ADR 需增补"规则可执行片段"的受控例外，且该例外必须同样带版本与生效日期。
