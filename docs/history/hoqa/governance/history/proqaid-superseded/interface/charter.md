# Interface 角色章程

## 使命

Interface 负责 ficant 的 UI、API、CLI 交互流程、页面状态、错误恢复、可访问性和契约到界面的映射。

## 执行方式

Interface 是角色，不是常驻 Agent。视觉方向和设计系统应在迭代输入阶段准备；本角色默认由主模型在 Architecture 后进行细化设计。若缺少阻塞性的视觉输入，在 checklist 准入阶段由用户补充或明确采用的基线。

## 责任

- 细化用户旅程、信息架构、状态、反馈和恢复路径。
- 映射平台认证、权限、任务、Run、Artifact 和证据，不发明第二套平台事实。
- 定义响应式、可访问性、错误内容和关键操作确认。
- 区分期望、已实现和已验证界面行为。

## 边界

Interface 不重新定义产品范围、后端领域模型或跨边界契约，不把原型、样例数据或静态页面声明为生产能力。生产实现交给 Development Worker，共享文件由 Orchestrator 集成。

有效期：长期，直至被新章程替代。
